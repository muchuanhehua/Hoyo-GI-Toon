# 原神新式 FaceSDF 读取专项

日期：2026-10-31。对应 P04-F03；R/A 主阴影重建已获用户确认并接入 2.2.0 源码候选。完整原游戏算法尚未确认，实际源码回归见[集成记录](../.verification/development/pmx-sdf-ra-integration-20261031/README.md)。

## 结论

奥黛塔这份 `_FaceSdfMap` 不能按旧 FaceLightmap 的 Alpha、RGB 转标量或单 R，直接视为完整阴影场。资源数据强烈支持 R/A 分段存储同一阈值场的假设：

```text
D = (R + A) / 2
R ≈ clamp(2D, 0, 1)
A ≈ clamp(2D - 1, 0, 1)
```

这是一条有数据依据、已做实际渲染的兼容重建候选，尚不能称作已还原原游戏新式 SDF 的完整读取算法。通道重编码吻合不证明原 shader 使用相同的光向函数、过渡或高光公式。

## 输入与参考

- 同角色 FBX 资产中的 Face 材质明确设置 `_UseFaceSDF=1`、`_UseFaceMapNew=0`，`_FaceSdfMap` 引用 FaceSDF；`_FaceMapTex` 为空。新旧资源按材质引用区分，不按角色名或年代猜测。
- 原值包括 `_NewFaceUseLegacySampling=1`、`_FaceSdfShadowSharpness=100`、`_FaceMapSoftness=0.0001`、`_EnableSdfSpecA=1`、`_EnableSdfSpecB=0`。这些值不能直接换算为旧节点的同名或近似参数。
- 图像为 1024² RGBA8；按 Non-Color、Channel Packed 读取，Alpha 作为独立数据，不参与颜色预乘。
- FBX 只在隔离的后台工程内通过 Better FBX 检查 UV。三个 Face 材质对象分别为 Face、Face_Eye、EyeStar；本次导入所得 UV0–UV7 在各对象内完全相同，没有可通过切换 UV 层解决本问题的证据。此结果不证明源 FBX 存有八套独立 UV。
- PMX 主脸使用其有效原 UV；不改源 UV，不把眼星等辅助几何当作主脸。

| 参考 | 本地源码及原始节点库的读取契约 | 本轮可借鉴部分 |
|---|---|---|
| Setup Wizard / PrimoToon v4 | Face_Lightmap 的 Alpha 进入脸部因子 | 数据色彩空间、资源赋值、旧式脸部与光向组织 |
| 晨星 Festivity / GI v3.4 | Face_Lightmap 的 Color 隐式转标量后参与脸部因子 | 保留原生组、明确替换资源、避免继承模板眼部遮罩 |

两个本地插件均未发现 `_FaceSdfMap` 与对应新参数的解码分支。本轮图像比较的是这些采样接法接入 HGT 共用 Face 链路的结果，没有把它们标为两个参考插件完整工作流的渲染。

公开的 [PrimoToon 主 shader](https://github.com/festivities/PrimoToon/blob/main/PrimoToon-main.hlsl) 和 [HoyoToon 原神脸部函数](https://github.com/Hoyotoon/HoyoToon/blob/main/Shaders/Genshin%20Impact/Includes/HoyoToonGenshin-common.hlsl#L430) 同样提供旧图 Alpha、头部光向、左右镜像及阈值比较的依据，不能作为这份新图的完整解码证明。已保存所读取片段与 Git blob 摘要。

## 数据与渲染验证

将真实主脸 UV 及其镜像覆盖到图像，检验上述重建后重新编码的误差：

| 实际 UV 范围 | 覆盖纹素 | 超过 1/255 的纹素 | 平均绝对重编码误差 |
|---|---:|---:|---:|
| FBX Face + Face_Eye | 575,498 | 112 | 0.00002351 |
| PMX 主脸 | 479,790 | 68 | 0.00001643 |

PMX 范围内约 99.986% 在一个 8 bit 码值以内，剩余误差仍保留记录；全图边缘有更大偏差。该比例仅描述通道数学关系，不是渲染还原率，也不证明其他角色通用。

固定 PMX、原 UV、相机、其他材质、阴影位置 0.52 和脸部软硬 0.02，比较 R、RGB 转值、Alpha、`(R+A)/2`、`R-A` 五种采样。每种覆盖正面、±20°、±45°、±90°、背面八个光向，共 40 张材质图、40 张主脸因子图；原参数 100 / 0.0001 未被冒充为旧节点参数。

- 仅 R：90° 侧光仍几乎全脸有亮因子，180° 背光仍留大半张亮面。
- R/A 重建：侧光进入半脸阴影，背光接近全脸阴影；近正面没有 Alpha 单通道出现的过早分半。
- RGB 转值与 Alpha：分别出现过早全暗或过早分半，不能直接拿来读新图。
- 以上支持继续采用 R/A 重建作为验证候选；没有受控游戏光向参考，不能据此确认其鼻影形状、角度响应与游戏完全一致。

主脸因子诊断保留所有材质槽，只替换主脸输出。曾替换辅助槽得到的全零探针已排除，不作为产品问题证据。有效诊断使用独立红色 ID 确定主脸范围，显示字节统计与线性着色因子分开解释。侧光、背光四张关键材质图另行重算，严格像素一致。

游戏截图保留为外观参考；截图与测试的姿势、光照不同，不计算游戏还原率，也没有按截图另调角色参数。

## 尚缺的依据与后续

尚未取得能读取此图的原 shader 或可信工作工程；公开代码检索也没有找到这些精确新参数的非 JSON 实现。仍需确认：

1. `_NewFaceUseLegacySampling` 的实际分支，以及光向到 R/A 两区间阈值的映射。
2. `_FaceSdfShadowSharpness` 的公式、插值与过滤方式。
3. G/B 的确切用途、SdfSpecA/B 与额外眼部遮罩之间的关系；不因命名就把 G/B 当成高光或眼罩。

F03 的完整游戏算法保持未确认。源码候选已采用用户确认的 R/A 主阴影兼容重建，旧式保持 Alpha；不发布、不安装、不恢复 FBX 导入入口、不进入单角色配置。

私有证据入口：[奥黛塔专项对照](../.verification/research/odette-new-sdf-20261031/README.md)。其中保留原图、UV 及通道测量、源节点图、渲染脚本、四张关键图重算和收尾摘要。

## 增补：新旧模型多光向

用户要求增加光照并对照旧模型，已完成安柏 Alpha、纳西妲 Alpha、奥黛塔 R 和 R/A 重建四列对照。水平 24 方位、上光八方位、下光八方位、换边四个细测，共 44 个条件、176 张材质图及 176 张主脸因子图。光向依据每位角色的头部参照对齐，其余材质、相机、原 UV 和共用参数固定。

| 模型／采样 | 90° 非黑脸区 | 180° 非黑脸区 | 背光 179°→181° 平均绝对显示差／255 |
|---|---:|---:|---:|
| 安柏 Alpha | 53.57% | 0.77% | 0.005969 |
| 纳西妲 Alpha | 48.56% | 0.09% | 0.000000 |
| 奥黛塔 R | 98.07% | 60.28% | 0.509959 |
| 奥黛塔 R/A 重建 | 49.52% | 0.90% | 0.006025 |

统计范围为红色 Face ID 与眼距归一的正面脸区交集，排除颈部及辅助材质。“非黑”阈值为 PNG 显示字节大于 8/255，表格不是线性因子或游戏还原率。不同脸型的绝对灰度不要求相等。

单 R 在 179°→181° 出现整片亮暗翻面，两个旧模型与 R/A 重建均无此大块跳变。上光、下光未改变这一判断。结合上一轮通道数据，**当前链路优先选择 R/A 重建作为主阴影兼容候选，旧式保持 Alpha**；格式判断使用材质开关与明确引用，不按角色年代或姓名猜测。

本次缩小了主阴影输入的选择范围，没有确认 LegacySampling、锐度或 G/B 完整公式。用户确认后，R/A 重建已接入 2.2.0 源码候选，运行实现移除单 R 分支；不发布、不安装。
