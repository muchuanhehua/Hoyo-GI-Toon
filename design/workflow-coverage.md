# 39–50 通用出图交付

本批先完成通用出图、工程与交付；35–38 单独角色材质检查、适配与配置放到最后，按角色逐一处理。当前验收聚焦通用功能、代表样本的共用材质链路与操作；逐角色精修不作为本批发布前置，34 共用基础材质外观结论单独记录。当前状态以 [开发进度](DEVELOPMENT.md) 为准，精确候选与验证摘要保存在 `candidate-v1.0.1.json`。

## 功能与模块

| 编号 | 实现 | 接口与边界 |
|---|---|---|
| 39 | 全身、半身、头像，正面、斜侧、侧面、背面，角度与留白 | `framing.points / bounds / frame` 读取当前姿态与勾选表面；临时求值排除描边和未实现的光向实例，保留源网格与变形。相机签名检测手动编辑，出图保留手动机位。 |
| 40 | 柔光、侧光、逆光，纯色或透明背景，可选地面 | `presentation.background / floor` 只创建本次输出资源；原场景灯光、世界和合成链保持独立。地面灯仅作用于地面。 |
| 41 | 尺寸、PNG、编号、任务进度、取消与再次出图 | `rendering.start / finish / output_path` 沿用原生渲染任务；临时 PNG 校验后才替换目标，取消清理临时文件并保留原图；源资产路径受保护。 |
| 42 | 已有表情强度、看向相机、重置及姿态跟随 | `expressions.initialize / apply / gaze / reset` 操作派生形态键和可移除视线约束；原形态键、动作、骨架通道、约束与 MMD 元数据可恢复。只提供已有顶点表情和眼骨操作。 |
| 43 | 导入、少量外观参数、三种取景、渲染为主线 | `panels.py`；构图、展示、表情、输出与附件折叠，只有存在有效数据时才展示相应控件。 |
| 44 | 保存重开、旧工程保留、移动资源重关联 | `project_io.stamp / on_load / relink`；记录源文件摘要，核对后更新资源路径，失败回滚，不重新导入资产。出图仅校验当前启用表面所用资源。 |
| 45 | 缺依赖与错误操作提示、帮助入口 | 单入口按格式调用 Better FBX 或 MMD Tools，缺依赖不替换后端；简短说明见 [使用流程](../docs/workflow.md)。 |
| 46 | 计时、重复刷新与资源计数 | 沿用导入批次归属，临时求值与渲染资源在完成或失败时释放；记录真实 FBX／PMX 导入、装配、刷新和构图耗时。 |

## 验证与验收

47 使用七个 FBX、三个 PMX 及受控材质夹具复验最终运行代码，覆盖早中后期、Loli／Girl／Lady、旧图集与分层眼、眼层、面料、反射、法线、采样、透明和表情深度。游戏截图、原文件和配套资产只读；测试图片与工程留在私有 `.verification/`。矩阵范围及基础材质依据见 [材质覆盖](material-coverage.md)。

48 结合四 FBX、三 PMX、五组主体、混合格式、旧工程和真实界面，检查单入口、分组、撤销重做、缺依赖、注入失败、保存重开、恢复、多角色隔离及实际异步 PNG。分组界面使用真实 FBX 和混合 PMX 夹具，构图／表情／视线界面使用真实 FBX 和 PMX 角色。旧着色对照使用已发布 0.5.3 的原构图函数固定相同机位，保留严格像素和 Alpha 判定；新增构图单独验证。`verify_workflow.py` 另检查真实 FBX／PMX 的构图、灯光、背景地面、表情、视线、姿态、手动相机、资源计数与文件移动；错误贴图须被拒绝，正确重关联前后的 PNG 像素须一致。

取消分两项记录：自动验证注入原生取消回调，检查部分 PNG 清理、已有文件保留、任务状态复位和再次实际出图；原生 Esc／状态栏取消按钮的实际输入留给最终操作验收。隐藏窗口的模拟输入不作为通过证据。

49 冻结候选后，从 ZIP 独立安装并重跑上述检查，按精确摘要收集证据，提交真实面板、图片和可重开工程，验收通用功能与操作。逐角色材质外观检查、适配和精修在 50 交付后按角色单独推进；实现、自检和打包均不替代对应用户验收。

50 在最终验收后执行正式发布、索引更新与本地安装更新。正式包复用已复验候选字节；已发布 0.5.3 和历史候选保留。构建入口为 `tools/build_release.py`，证据汇总为 `tools/collect_verification.py`。
