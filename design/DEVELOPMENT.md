## 2.6.0 确认前诊断依据（2026-11-03）

用户询问阴影位置与打光关系、拖灯卡顿、上下可编辑的描边渐变及整体阴影软硬。确认前已核对源码并在独立后台工程采样；以下保留诊断依据，确认后的实施状态以上方为准。

- 阴影位置实际连接原生 Body／Face 的明暗分界阈值，主光方向仍驱动角色阴影，脸部还使用相对头部方向。建议改名为高级的明暗分界偏移，日常通过主光控制；默认太阳光调旋转，移动位置不改变光向。
- CPU 实测旋转预设光的中位耗时：安柏约 34.4 ms、纳西妲 72.5 ms、奥黛塔 228.1 ms；在独立副本关闭描边分别约 1.5／11.1／22.2 ms。仅关闭光向修改器的视口开关未消除昂贵的描边求值。进一步隔离奥黛塔：停用 GI-Toon 依赖图更新回调后只转太阳光约 1.6 ms，单独转插件光向参照对象约 206.6 ms，说明光向参照的变换会连带网格／描边求值。瓶颈已复现；下一轮优先研究光向改走着色参数、移除打光对描边几何的依赖，并只写实际变化的灯光属性，不能把关闭描边当作交付方案。以上为 CPU 更新耗时，未测 GPU／实际视口整帧；上轮预览响应检查不等于拖灯流畅度验收。
- 当前描边为静止高度 smoothstep，底端可调、顶端固定为 1。用户希望双端及过渡可编辑的高度渐变；建议总粗细乘以高度曲线，顶部／底部系数、过渡位置与中间控制点可编辑，继续随原静止高度及蒙皮移动。
- 当前明暗过渡控制身体／头发，脸部软硬控制 SDF，两条计算链不同。建议以整体阴影软硬联动角色明暗交界，脸部保留高级补偿；实际场景投影软硬继续由光源尺寸／角度控制，不能仅改显示名称。

原始 CPU 数据及脚本：`.verification/development/lighting-feedback-20261103/report.json`、`handler-report.json`。三个输入工程摘要与正式 Python 代码保持；用户确认的四项已完成 2.6.0 发布与本地更新；以上保留诊断时的数据，最终结果以上方当前状态为准。

## 用户流程

已有模型：选中角色网格、骨架或 MMD 根 → 应用材质 → 调材质、灯光与相机 → 原生渲染。

新模型：导入 PMX → 应用材质 → 调整 → 原生渲染。导入自动修骨；已有模型接入不重复修骨。导入仅在场景没有相机时创建相机，构图由用户设置。

图片尺寸、保存和动画渲染使用 Blender 原生功能。材质应用同步 Eevee／Standard 的 Toon 条件，原相机、输出设置和合成设置保留。表情与动作继续通过 MMD Tools／Blender 管理。
